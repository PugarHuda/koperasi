# 06 · QA and testing (QA Engineer), 8 Nov 2026

Builds on [05-security-8nov](05-security-8nov.md).

## Setup

- **Projects:** Playwright with 6 projects: `desktop` (Chromium 1440), `firefox`, `webkit`, `tablet` (iPad), `mobile`
  (Pixel 7), `iphone` (iPhone 13). Failures keep their trace and screenshot (`playwright.config.mjs`).
- **No fake chain.**
  - The page reads the live testnet.
  - The wallet panel is tested through `?as=<account>` previews, which only run on localhost.
  - The edge-case states (no rule voted, a task awaiting approval) answer chosen views through route interception (`answerViews`); every other call goes to the real network.
  - Transactions themselves were not signed in E2E, because there is no headless wallet for NEAR testnet. Instead, the main flow was run for real with the scripts (tx hashes in [03](03-contract-8nov.md)).
- **Accessibility:** `@axe-core/playwright` in `resilience.spec.mjs`.
- **Visual:** `@visual`, the header and hero screenshots per project.

## Bugs found by QA

| Bug | Cause | Fix |
|---|---|---|
| Firefox: "join deposit fails with a readable message" failed on both attempts. The double-click landed on the word "join" in the heading, not on the button. | **Layout shift:** section 06 filled after the rest of the page and pushed the join panel down under the pointer. Real users could misclick the same way. | The board's data is read together with the main data and rendered in the same pass (`web/app.js`, `trustBoard`). Verified 3× on 3 projects. |
| Panel reads ran in a serial round (slow under rate limits) | the task reads were awaited after everything else | merged into the first `Promise.all` (`web/wallet.js`) |

## Flakiness that remains

All of it comes from the public testnet RPCs under parallel load: 429s, slow views, and the "Could not read the
co-op: NetworkError" message, which is the app's correct error state. The page has an RPC failover and shows an error
message; the tests have 1 retry.

## Not covered

- Real wallet signing in the browser (no headless NEAR wallet).
- Wrong network: the connector is opened for testnet only.
- Transaction tests against a local node: there is no Sputnik/global-contract sandbox in this repo. Testnet was used directly, with the tx hashes in [03](03-contract-8nov.md).
